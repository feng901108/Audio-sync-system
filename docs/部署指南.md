# 部署指南

## 前置要求

- NAS 已安装 Docker 和 Docker Compose
- NAS 与所有播放设备在同一局域网内
- 建议 NAS 使用有线网络连接
- 音乐文件已存放在 NAS 可访问的目录中

## 快速开始

### 1. 准备配置

复制环境变量示例文件：

```bash
cp .env.example .env
```

编辑 `.env` 文件，修改音乐库路径：

```
MUSIC_DIR=/path/to/your/music/library
```

> 注意：`MUSIC_DIR` 是 NAS 上的实际音乐文件夹路径，需要绝对路径。

### 2. 创建 FIFO 管道

首次运行前需要创建音频管道文件（Mopidy → Snapserver）：

```bash
mkdir -p /tmp/audio
mkfifo /tmp/audio/snapfifo
```

> 由于我们使用 Docker volume 共享管道，实际管道会在容器启动时自动创建于 volume 中。
> 以上命令仅供理解原理，无需手动执行。

### 3. 启动服务

```bash
docker compose up -d
```

查看服务状态：

```bash
docker compose ps
```

查看日志：

```bash
docker compose logs -f snapserver
docker compose logs -f mopidy
docker compose logs -f mympd
```

### 4. 扫描音乐库

首次使用需要扫描音乐文件：

```bash
./scripts/scan-library.sh
```

或直接执行：

```bash
docker compose exec mopidy mopidy --config /etc/mopidy/mopidy.conf local scan
```

### 5. 访问控制界面

| 界面 | 地址 | 说明 |
|------|------|------|
| myMPD Web 控制 | `http://<NAS_IP>:8080` | 音乐播放控制界面（推荐） |
| Snapweb | `http://<NAS_IP>:1780` | Snapcast 客户端管理界面 |
| Mopidy HTTP | `http://<NAS_IP>:6680` | Mopidy 原生 Web 界面 |

## 端口说明

| 端口 | 协议 | 服务 | 说明 |
|------|------|------|------|
| 1704 | TCP | Snapserver | 音频流传输 |
| 1780 | TCP | Snapserver | HTTP 控制 + Snapweb |
| 6600 | TCP | Mopidy MPD | MPD 协议控制 |
| 6680 | TCP | Mopidy HTTP | Mopidy HTTP API |
| 8080 | TCP | myMPD | Web 控制界面 |

## 常用操作

### 启动/停止服务

```bash
# 启动
docker compose up -d

# 停止
docker compose down

# 重启
docker compose restart
```

### 重新扫描音乐库

```bash
./scripts/scan-library.sh
```

### 查看客户端连接状态

访问 `http://<NAS_IP>:1780` 或使用命令行：

```bash
docker compose exec snapserver snapserver -v
```

### 更新镜像

```bash
docker compose pull
docker compose up -d
```

## 配置调优

### 调整缓冲延迟

编辑 `config/snapserver/snapserver.conf`：

```ini
[buffer]
ms = 1000    ; 默认 1000ms，可根据网络质量调整
              ; 网络好可以调小（如 500ms），网络差调大（如 2000ms）
```

### 调整音频编解码器

编辑 `config/snapserver/snapserver.conf`：

```ini
[streaming]
codec = flac    ; 可选：pcm, flac, ogg, opus
                ; flac - 无损，适合局域网
                ; opus - 有损高压缩，适合低带宽
```

修改后重启服务：

```bash
docker compose restart snapserver
```

## 客户端安装

服务端部署完成后，需要在各播放设备上安装客户端。

### 安卓手机

推荐使用 **Termux + snapclient** 方案：

```bash
# 在 Termux 中执行
bash scripts/termux-install.sh <NAS_IP>
```

详细步骤请参考 [客户端安装指南](客户端安装指南.md)。

### 小米电视

由于电视没有触摸屏，操作 Termux 困难，提供两种方式：

**方式一：ADB 一键安装（推荐）**

在电脑上执行：

```bash
bash scripts/tv-adb-install.sh <电视IP> <NAS_IP>
```

**方式二：继续使用 Snapdroid**

如果 ADB 方案太复杂，Snapdroid 仍然是一个简单可靠的选择：
- 下载：https://github.com/badaix/snapdroid/releases/tag/v0.29.0.2
- 虽然更新慢，但核心播放功能稳定

### Mac

```bash
brew install snapcast
snapclient -h <NAS_IP>
```

## 故障排查

### 没有声音

1. 确认客户端已连接到服务器（检查 Snapweb 界面）
2. 确认 Mopidy 正在播放（检查 myMPD 界面）
3. 检查客户端音量是否静音
4. 查看服务日志：`docker compose logs`

### 不同步

1. 确认所有设备都在同一局域网
2. 尝试增大缓冲：`buffer.ms = 2000`
3. 在 Snapweb (`http://<NAS_IP>:1780`) 中微调每个客户端的延迟偏移
4. 优先使用有线网络或 5GHz WiFi

### 找不到音乐

1. 确认音乐目录路径在 `.env` 中配置正确
2. 重新扫描音乐库：`./scripts/scan-library.sh`
3. 检查文件格式是否支持（MP3, FLAC, AAC, WAV 等）

### Docker 启动失败

1. 检查端口是否被占用：`netstat -tlnp | grep -E '1704|1780|6600|6680|8080'`
2. 确认 Docker daemon 正在运行
3. 查看详细错误日志：`docker compose logs`
